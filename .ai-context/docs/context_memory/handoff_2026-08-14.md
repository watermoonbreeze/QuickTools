1. **myinit 双模型初始化**:建立了完整的 `.ai-context/` 结构(`PROJECT.md`/`public-agent-rules.md`/发布协议三件套/`docs/feature/`)+ 根 `CLAUDE.md`/`AGENTS.md` + `.claude/`/`.codex/` 专属入口
2. **分析了旧项目 `adblistener`**(`D:\Company\Gitee\adblistener`,Java+JavaFX+手写MVP)的完整功能清单,写成 `docs/feature/adblistener-migration-map.md`,包含跨平台隐患清单(shell 管道依赖、`SimpleDateFormat` 线程安全、无界日志内存问题)
3. **分析了参考项目 AYA**(用户桌面上的截图):确认是 Electron + TypeScript 技术栈(`custom-electron-titlebar` 自绘标题栏,`app.asar` 打包),布局是顶部 Tab + 设备选择器常驻 + 按数据类型选组件
4. 经过多轮讨论,确定了完整架构方案,写进 `docs/feature/roadmap.md`,核心决定:
   - **可插拔工具框架**:`core-api` 定义 `ToolPlugin` 契约,每个工具是独立 Gradle 模块(`tools/*`)
   - **三层插件加载**:内置模块(编译期,主线)→ 外部 JAR 插件(`ServiceLoader`,进阶阶段)→ 脚本插件(GraalVM Polyglot,先 JS/TS 后 Python,远期,类似 uTools 但不内嵌浏览器)
   - **UI 是"启动器 + 独立窗口"两层**(不是最初设想的 AYA 式顶部 Tab 壳):启动器主窗口 = uTools/Raycast 式工具网格+搜索,点击工具后新开独立 `Window`。AYA 的顶部 Tab/设备选择器布局降级为"单个工具窗口内部"的参考,不是全局壳——因为大部分工具跟"当前设备"无关
   - **主题系统**:预设主题 + 明暗切换 + 强调色驱动的自定义主题,统一走 `ThemeSpec` 渲染路径
   - **性能目标**:明确对标"比 Electron 轻、启动快、内存低",具体落地点(有界日志缓冲、协程替代线程回调、避免不必要重组)记在 roadmap 技术选型清单里
   - **平台范围**:Desktop-only(单一 `jvm()` target),但必须真正跨 Windows/macOS/Linux,不是只兼容 Windows
5. **针对用户 Java 背景做了教学节奏调整**:路线图第一个阶段是 Phase 0a(在现有两模块脚手架里直接写最简版颜色转换,建立 Kotlin 语法+Compose 声明式心智模型的手感),之后才是 Phase 0b 多模块改造。这条也写进了 `public-agent-rules.md` 第 7 条
